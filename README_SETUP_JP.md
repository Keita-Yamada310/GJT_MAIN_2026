# GJT単独版・Teams配布（2026-10-04）

既存の本実験30項目A/Bと最新の練習フィードバック実装を使用。Outside exposureは削除。
このフォルダの中身だけをGitHubリポジトリのルートへアップロードする。
名簿、割り当て表、秘密鍵、回答CSVをGitHubへアップロードしない。

## 設定
1. assets/config.js の DATAPIPE_EXPERIMENT_ID に、個人Google Driveへ接続した既存DataPipeのExperiment IDを入れる。
2. GitHub Pagesを有効にする。既存リポジトリでは古い入口を残さず、この構成に更新する。
3. 公開URLの末尾に以下を付けてTeamsへ掲載する（学科ごとに同じリンクを利用可能）。

| チームの割当系列 | プリのリンク | ポストのリンク |
|---|---|---|
| AB | pre_A/ | post_B/ |
| BA | pre_B/ | post_A/ |

例： https://ユーザー名.github.io/リポジトリ名/pre_A/
チーム名は「M_系列AB」「M_系列BA」のように固定すると、ポストのセット名と混同しにくい。
チームメンバーは固定し、各時点の指定リンクのみ投稿する。終了したプリ投稿は削除するか明確に無効扱いにする。

## 本人入力と割当
最初の入力画面は「ID（学籍番号）」「氏名（日本語）」の2段。入力環境のプルダウンなし。
学籍番号は全角数字を半角化、空白を除き5桁を確認する。氏名は入力確認画面を表示。
氏名の照合用列は空白除去・𠮷→吉を行う。原入力の氏名もCSVに記録する。
このTeams配布版は名簿との自動照合・自動割当・Teams認証を行わない。
セットはURLで固定される。別チームのリンクを共有すると別セットも開ける。
identity_verified=false、allocation_method=teams_fixed_linkを記録。
counterbalance_sequenceはリンクから推定した系列であり、名簿の予定割当と別途照合する。
予定割当表と実データの学籍番号・氏名・gjt_set・administration_labelを照合して誤入力・誤セット・重複を確認する。
氏名・学籍番号は保存先CSVに含まれるため、Google Driveの保存先を非公開で管理する。

## 実施・保存
PCキーボードのみ。A=No、L=Yes。練習2問は正誤フィードバック、本課題30問はなし。
本課題は参加者ごとにランダム化、正文15/非文15、各10秒。刺激文は変更していない。
GJTを保存して終了し、アンケートは表示しない。プリ/ポスト・A/BをCSVとファイル名に記録。
DataPipeのHTTP202は保存先への送信待ち。Drive上のファイルを担当者が確認する。
失敗時は再試行ボタンとローカルCSV保存。重複送信の有無はセッションIDで確認する。
保存先未設定・スマホの場合は開始しない。タッチ対応PCも検出条件で止まる場合があるので本番端末で確認する。
URL自体には実施期限の制限がない。プリ・ポスト以外の時期のアクセスは運用で管理する。

## 本番前の確認
4リンクを実際に開き、学籍番号・氏名の入力、修正、練習FB、A/L、30問、終了を確認。
各リンクから回答しDriveにCSVができること、プリ/ポストとセットが正しく記録されることを確認。
40人の同時保存はこのパッケージ作成時点では未検証。事前に同時試行してDriveの受信件数を確認する。
名簿との自動照合が必要な場合は、以前の非公開Google照合方式を追加する必要がある。
